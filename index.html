Hand-off flow

Since the WCH staging server went live the corpus moves in one direction: fetch the deposit, convert the vendor formats, push the open files to WCH, then delete only the mz(x)ML we pushed. Vendor originals stay here until a destination exists for them, so data-ready being near-empty is the system working, not an idle pipeline.

Disk headroom

Two volumes with separate limits, so they are read separately. Botnet holds data-download — every vendor original we keep — and carries the 5,120 GiB (~5.50 TB) floor; its freed blocks are not returned promptly, so it only ever grows. gscratch holds data-ready, which mzML passes through on its way to WCH; it does release space on deletion, and it is shared with other users, so the free figure moves for reasons that have nothing to do with us.
